## 4. 已完成的实现（可信任的部分）

### 4.1 `sd_spi`（SPI 主机，50MHz 域）
- 状态机：`S_IDLE → S_PUP(80clk 上电) → S_SEND6 → S_POLL(R1) → S_BR → ...`
  初始化分支：`S_C0CHK → S_C8CHK → S_A55R → S_A41R → S_C58CHK → S_C16CHK → S_DIV → S_READY`
- 命令：CMD0(0x95 CRC) → CMD8(0x87) → CMD55 → ACMD41 → CMD58 →（SDSC 才 CMD16）
- 支持 SDHC（`ccs=1`，块寻址）/ SDSC（`ccs=0`，字节地址左移 9）
- 字节引擎：`eng_ld` 装载 → 8 个 SCLK → `eng_done`，下降沿同时采 MISO + 移出 MOSI
- 分频：初始化 390kHz（`DIV_INIT=63`），读块 6.25MHz（`DIV_FAST=3`）
- 读块：`rd_go` 脉冲 → CMD17 → R1 → 0xFE token → 512 字节 → CRC2 → `blk_done`
- **地址锁存**（重要）：`if (rd_go) rdaddr <= ccs ? rd_addr : {9'd0, rd_addr[22:0]};`
  CMD17 帧用锁存的 `rdaddr`，因为 `rd_go` 是单拍脉冲。
- 诊断输出：`step[4:0]`（sticky 里程碑）、`r1b[7:0]`（ACMD41 的 R1）

### 4.2 `sd_img`（FAT32 + BMP 解析 → 128×96 缩略图）
- 状态机（**编号已用于屏幕诊断，改动时务必同步文档**）：
  ```
  0 S_W0     发起/重试初始化
  1 S_WI     等 init_done / init_err
  2 S_MBRI   读 LBA 0 (MBR)
  3 S_MBRW   收 MBR
  4 S_MBRE   判断分区类型
  5 S_BPBI   (未使用)
  6 S_BPBW   读/收 BPB
  7 S_BPBE   ★ BPB 校验 —— 当前卡在这里
  8 S_DREAD  读簇内扇区
  9 S_DWAIT  收扇区 (目录项扫描 / BMP 像素)
 10 S_FATI   读 FAT 项
 11 S_FATW   收 FAT 项
 12 S_FATE   沿簇链前进 / 结束
 13 S_DONE   完成 (tf_valid=1)
 14 S_ERRW   出错等待 3s 重试
  ```
- 像素抽取：加法器抽点（零乘法器），`accx += 128` 判定、`accy += 96` 判行
- 调色板：RGB888 高 4 位 → `tf_map` (4096×4bit ROM) → 4bit 索引 → 写 `tf_ram`
- 超时看门狗：`tmo` 24 位（≈335ms 无新字节即放弃），覆盖 MBRW / BPBW / DWAIT / FATW
- 诊断输出：`fdiag[1:0]`、`dsel[2:0]` 输入 + `dbg[7:0]` 输出（轮询显示 BPB 字段）

### 4.3 显示层
- `gal_layer`：相册页，512×384 图片窗（逻辑坐标 64,44），1.25× 放大到 640×480
- `tf_valid=0` 时显示**诊断画面**：青底(07FF) + 红窗(F800) + 两排各 8 个方块
- 第二排方块轮询显示诊断字节，项间 `dfill` 消隐

### 4.4 游戏栈（保留）
RPG 游戏、BGM、频谱彩条、按键矩阵全部保留；10 秒无操作进相册，任意键回游戏。

## 5. 当前唯一的 Bug：BPB 校验不过（状态码 7）

### 5.1 现象
- 第一排方块稳定亮 5 个（`step[0..4]` 全过 = SPI 初始化完全正常，卡已就绪 R1=0x00）
- 第二排稳定显示 `0x0E`（右起 2/3/4 亮）= `state = 7` = `S_BPBE`
- 卡在电脑上确认：**FAT32 文件系统，根目录有 24bit BMP**

### 5.2 校验条件（key_debounce.v 内部 `S_BPBE`）
```verilog
if (bps_lo == 8'h00 && bps_hi == 8'h02 && nfats != 8'd0 &&
    fatsz != 32'd0 && rootclus >= 32'd2 &&
    (spc == 4'd1 || spc == 4'd2 || spc == 4'd4 || spc == 4'd8))
```
即：每扇区 512 字节、有 FAT、FAT 非空、根簇 ≥2、每簇扇区数 ∈{1,2,4,8}。

### 5.3 已排查并排除的可能
- ❌ 引脚错（已用底板原理图确认 F13/F14/F15/D14）
- ❌ SPI 时序（CMD0/8/55/41/58/16 全部有正确应答）
- ❌ exFAT 卡（用户确认 FAT32）
- ❌ 没有 BMP 文件（已在根目录放 `sd_test.bmp`）

### 5.4 已做但未验证的修复（**上一轮改动**）
| 改动 | 位置 | 说明 |
|---|---|---|
| `fat_sec` 右移 7 位 | `wire [31:0] fat_sec = fat_lba + {14'd0, cur_clus[31:7]};` | 原为 `{cur_clus[24:0], 7'b0}` 左移，错 |

## 7. 调试方法论（血泪经验，务必遵守）

### 7.1 验证脚本 `tools/verify_sd.py` 的局限
它做三件事：① 造 4096 扇区 FAT32 卡镜像（含 640×480 BMP）② 用 Python 复刻 RTL 算法
③ 与独立参考实现逐像素比对 ④ lint。

**⚠️ 最大的坑**：Python 模型里 FAT 寻址**一直是正确实现**，所以"逐像素一致 12288/12288"
全绿了 N 轮，但 RTL 里的 `fat_sec` 是错的。**逐像素比对只能证明"模型对"，证明不了"RTL 对"。**

已加入 **RTL 语义回归**（`verify_sd.py` 的 lint 段），目前 9 条：
1. `fat_sec` 必须是 `cur_clus[31:7]`（右移 7）
2. FAT 项在 `fat_off` 处写 `fatent[7:0]`（小端）
3. 目录项必须有 `5'd21: echi[15:8]` 捕获 + `fcl <= {echi,`
4. 必须存在 `S_A55R:` 状态（CMD55 后真发 ACMD41）
5. `output reg [13:0] tw_addr`（12288 像素需 14 位）
6. 至少 4 处 `tmo == 24'hFFFFFF`（超时看门狗）
7. `if (rd_go) rdaddr <=` 且 `cmdsh <= {8'h51, rdaddr`（地址锁存）
8. `sd_spi` 模块体内不得出现 `cnt`/`dsel`/`dbus`/`fdiag`/`b450`/`echi`（防 HDL-8007 跨模块引用）
9. `S_READY` 内不得出现 `step <=`（防无限重启）

**新增 RTL 前先跑一遍，改完再跑一遍。**

### 7.2 已踩过的 TD 报错
| 错误码 | 含义 | 对策 |
|---|---|---|
| `8007` | 信号被多个 always 块驱动 | 各 always 块职责分离，复位分支别重复写别人的信号 |
| `9019` / `USR-8091` | `.adc` 里有非法命令（整行 `//` 注释） | ADC 文件零注释 |
| `8472` | BRAM 不够（原设计需 106 块 > 芯片 64 块） | 已裁掉 photo_rom/动画层等，现约 10 块 |
| `8007` (HDL-8007) | 跨模块引用未声明信号 | `sd_spi` 里误用了 `sd_img` 的 `cnt` |
| `HDL-5007` | 常量位宽截断（`27'd150_000_000`） | 计数器位宽与常量必须匹配 |

### 7.3 板上诊断手段
- **第一排方块**：SPI 初始化里程碑（0~4 = CMD0/CMD8/ACMD41/CMD58/CMD16/块长）
- **第二排方块**：轮询字节（见第 2 步表格）
- **窗色**：红=无卡/初始化失败，黄=目录无 BMP，品红=BMP 格式不符
- LED：原为音频 R-2R DAC（游戏时随音乐闪，正常）

2. **先验证第 1 步**（重启死循环是否修好）。如果第一排还是全暗，先修这个，否则拿不到任何有用读数。
3. **第 2 步的 8 个读数是唯一可靠的信息源**。没有读数就改代码 = 盲改，已经浪费了很多轮综合时间（每轮综合约 5~10 分钟）。
4. **如果读数采集太麻烦**，一个替代方案：把 `sd_img` 的关键字段（`mbr_type`/`bps`/`spc`/`rsvd`/`nfats`/`fatsz`/`rootclus`/`mbr_lba`）
   直接经 UART 打印出来（板上有 UART，引脚需查原理图）。这比在屏幕上数方块高效得多，**推荐优先考虑**。
5. **考虑用仿真验证 FAT32 路径**。如果能拿到 TD 的仿真环境（或改用 iverilog + 把 `$readmemh` 路径改成本地），
   用 `verify_sd.py` 造的卡镜像喂给 `sd_spi`+`sd_img` 的 testbench，能直接看到 `state` 走到哪一步、
   `cnt` 卡在哪个字节。这比上板调试快一个数量级。**这是最推荐的下一步。**

## 10. 接手后的实际修复与当前交付状态（2026-10-30）

### 10.1 对历史判断的修正

- 当前故障不能归结为单个 BPB 判断。读请求同拍 `rdaddr <= ...` 和 `cmdsh <= {...rdaddr...}` 使用了旧地址，这是 Verilog 非阻塞赋值的确定行为；MBR 后请求分区 BPB 实际仍读 MBR。
- 旧 SDSC 表达式 `{9'd0, rd_addr[22:0]}` 没有左移，必须将 9 个零放在低位。
- `0x0E` 是十进制14，即 `S_ERRW`，不是 `S_BPBE=7`；校验失败后只在状态7停留一拍，随后等待3秒。
- `ds_cnt[2:0]` 每个系统时钟切换，不是每0.5秒切换；旧方块窗口只有6个位置且索引未减起点，不能可靠读取8位。
- Python 模型先加后比较，旧 RTL 比较旧值且减法覆盖加法。640×480 在旧RTL中只覆盖107列×80行；原脚本全绿无法证明硬件正确。
- 引脚依据扩展底板原理图，保持CS=F13、CLK=F15、MOSI=F14、MISO=D14；仅纠正文档和顶层过时注释。

### 10.2 已修改内容

- `sd_spi` 新增 `S_RDSTART=20`，请求拍锁存当前地址，下一拍组CMD17；SDSC正确左移9位。
- 错误时撤销 `init_done`；两处初始化入口恢复390kHz，初始化响应保存R1并校验CMD8、CMD55和CMD58，拒绝错误OCR冒充成功。
- `sd_img` 的SPC和簇内扇区计数扩为8位，支持1/2/4/8/16/32/64/128扇区/簇；对应簇地址移位同步扩充。
- 只选根目录第一个有效BMP，命中后不再被后面的BMP覆盖；目录结束标志保持；FAT32首簇/FAT项屏蔽保留高4位。
- 横纵抽样均比较并减去加法后的累加值；保留“多个源像素写同一目标点，后写覆盖”语义。
- BMP校验完整检查BM、DIB头、planes=1、24bpp、BI_RGB、像素偏移；文件或簇链提前结束不再将未填满RAM视为有效。
- 初始化等待计数器改29位，容纳10秒500,000,000拍。旧28位常量会被截断。
- 诊断每项0.5秒，显示0.4秒、消隐0.1秒；八项一轮4秒。方块32px周期，16px亮块+16px间隙，完整显示8位。错误码总线改成两级寄存器同步。
- BPB字段仅在读BPB时更新，错误等待期间保留，不再显示A5或被图片数据覆盖。

### 10.3 当前支持范围及未完成事项

- 保留原RPG、声音、游戏/相册切换和现有时钟、TF引脚约束；设计RTL仍放在TD已包含的文件中。
- FAT32：512字节扇区，首个MBR分区类型0B/0C，或LBA0直接为带FAT32标识的BPB。暂不支持exFAT/GPT、子目录搜索。
- BMP：未压缩24位，宽128～65535，高的绝对值96～65535，正/负高度均支持。小于128×96的图报格式错误，当前不实现放大填充。
- 当前只有一张TF缩略图缓存，所有相册页共用。轮播多文件、SDRAM搬运、HDMI音频包和Flash固化不属于本轮修复。
- 本地离线仿真不能代替TD综合/布局布线、时序收敛及实物TF卡测试。未操作原TD工程输出，也未下载或烧写FPGA/TF卡。

## 11. 图片文字清晰度改进（21:00实物反馈后）

用户已确认上一版可以自动播放；模糊的是BMP图片里的文字，并非游戏字库。旧缓存仅128×96，把640×480原图每约5×5像素压缩到一点，放大后丢失的小字笔画无法恢复。

本轮将TF图片缓存提高到 **256×192、4bpp、49152像素、24576字节**。保持原512×384逻辑显示窗口和16色调色板，放大倍数从4改为2。读取写入地址、顶层连接、视频地址、RAM均同步扩为16位。横向列计数8位，纵向行计数8位；写入地址为 `{row[7:0], col[7:0]}`。视频窗外地址钳位到0。

当前支持的BMP最小尺寸改为 **256×192**，仍为24bpp BI_RGB。现有640×480的 `sd_test.bmp` 不用转换；小于256×192会报格式错误。游戏、SPI模块体及TF引脚保持不变。

新回归命令：

```powershell
python tools/verify_sd.py
python tools/verify_sd_rtl.py --spi --diag --display
```

独立参考结果比对全部49152个像素；新增显示/RAM集成测试实际读写全部49152个RAM地址，并检查每个2×2放大块首尾输出、32767/32768边界及窗外钳位。**最终39/39项实际RTL回归通过**，包括原640×480测试BMP、负高度/填充、各簇大小、错误文件、SPI、诊断和RAM显示测试；显示测试共98304个地址/RGB样本全部通过。`verify_sd.py` 同样ALL CHECKS PASSED；完整顶层Verilog语法/接口编译无警告（不含厂商加密VHDL/真实PLL验证）。结果见 `sim/sd/out/results.json`。
