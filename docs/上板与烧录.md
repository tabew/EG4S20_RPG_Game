# 上板与烧录（安路 TD + HX4S20C）

> 本文按 TD（Tang Dynasty）通用流程写。不同版本的菜单名可能略有差异，
> 关键步骤和判断依据是一样的。

---

## 零、先别急着烧：这 4 处必须改完，否则烧进去也没画面

工程里**故意留了 4 个占位**，这是为了让代码能脱离具体板子综合和仿真。
烧之前必须补齐，不然现象是「HDMI 没信号」或者「有信号但只有边框没有字」。

| # | 位置 | 现状 | 要改成 |
|---|---|---|---|
| 1 | `rtl/clk_gen.v` | PLL 是**透传占位**（clk_pix = clk_p5x = 50MHz）| 换成 TD IP Generator 生成的 PLL |
| 2 | `constraints/rpg_pins.adc` | 所有 `LOCATION` 都是**占位值** | 按板卡原理图逐条改 |
| 3 | `rtl/video/tmds_serdes.v` | 没定义 `USE_ODDR_PRIM` 时是**行为模型** | 接安路的 DDR 输出原语 |
| 4 | `rtl/gen/*.hex` 路径 | 相对路径 `rtl/gen/xxx.hex` | 确认 TD 的工作目录能读到 |

第 1 项最容易被忽略：透传占位能综合、能布局布线、能生成 bit、能烧进去，
**但显示器一定黑屏**——因为像素时钟是 50MHz 而不是 25.175MHz，时序全错。

---

## 一、装工具

### 1. TD（Tang Dynasty）

安路官网下载 TD，安装后是图形 IDE，自带综合、布局布线、时序分析和下载工具。

### 2. 下载器驱动

TD 安装目录下一般有 `driver/` 或 `usb_driver/`，里面是 USB 下载器的驱动。
插上板子后设备管理器里应该出现安路的 USB 设备；没出现就是驱动没装。

板子上通常是这两种之一：

- **板载 USB 转 JTAG**（一根 Type-C/Micro-USB 线就能下载，最省事）
- **外接 AL-Link 下载器**（排针接 JTAG：TCK/TMS/TDI/TDO/GND）

---

## 二、建工程

### 1. 新建工程

- 器件系列：**EG4**
- 型号：**EG4S20BG256**（HX4S20C 板子上就是这颗）
- 工程放在仓库根目录（`eg4s20_rpg/`）下一层，比如 `td_project/`

> 工程目录放在仓库根目录附近很重要，因为 ROM 用的是相对路径。

### 2. 加设计文件

按顺序加入（顶层最后加也行，TD 靠 Top Module 设置认顶层）：

```
rtl/rpg_top.v            ← Top Module 设成这个
rtl/clk_gen.v
rtl/common/reset_sync.v
rtl/common/key_debounce.v
rtl/video/vid_timing.v
rtl/video/tmds_encoder.v
rtl/video/tmds_serdes.v
rtl/video/hdmi_tx.v
rtl/video/rpg_video.v
rtl/gen/ui_rom.v         ← 4 个 ROM + 数据表
rtl/gen/rpg_msgs.v       ← 精灵基址表
rtl/ctrl/rpg_core.v
```

### 3. 加头文件搜索路径

`rpg_core.v` 里有 `` `include "rpg_defs.vh" ``，要把它所在目录加进 include 路径：

```
工程设置 → Verilog / Include Path → 添加 rtl/gen
```

不加会报 `Can't find include file rpg_defs.vh`。

### 4. 加约束文件

```
constraints/rpg_pins.adc   引脚
constraints/timing.sdc     时序
```

TD 里在「约束」相关的页签添加；`.adc` 是安路自己的引脚约束格式，
`.sdc` 是时序约束（TD 支持 SDC 子集）。

## 三、改 PLL（第 1 项前置条件）

用 TD 的 **IP Generator → PLL**：

| 项 | 值 |
|---|---|
| 输入时钟 | 50 MHz |
| clk_out1 | **25.175 MHz**（像素时钟）|
| clk_out2 | **125.875 MHz**（5× 像素时钟，给 TMDS）|

生成后会得到一个 PLL 模块。把它填进 `rtl/clk_gen.v` 里注释掉的那段：

```verilog
pll_ip u_pll (
    .clk_in1  (clk_in),
    .clk_out1 (clk_pix),     // 25.175MHz
    .clk_out2 (clk_p5x),     // 125.875MHz
    .locked   (locked),
    .reset    (~rst_n)
);
```

同时把文件底部那三行「透传占位」的 `assign` 删掉。

**配不出小数分频怎么办**：直接用 25.000 / 125.000 MHz。帧率变成 59.5Hz，
绝大多数显示器照样认——字符游戏不在意这 0.5Hz。

**怎么确认改好了**：布局布线后看时序报告，clk_pix 的周期应该在 39.7ns 附近
（25.175MHz），而不是 20ns。

---

## 四、改引脚

打开 `constraints/rpg_pins.adc`，对着 HX4S20C 原理图逐条改 `LOCATION`。
一共才十几条：

| 信号 | 说明 | 注意 |
|---|---|---|
| `clk50` | 50MHz 晶振 | |
| `rst_key_n` | 复位按键 | 低有效 |
| `key_n[3:0]` | 4 个用户按键 | 低有效，按下接地 |
| `led[3:0]` | 4 个 LED | 可选，用来确认程序跑起来了 |
| `hdmi_clk_p/n` | HDMI 时钟对 | **必须是真差分对** |
| `hdmi_d_p/n[3:0]` | HDMI 数据对 | **必须是真差分对** |

HDMI 那 5 对是最容易出错的：

- 必须落在支持 LVDS 的差分对上，P/N 必须是同一组的相邻引脚
- TD 只约束 **P 端**，N 端由工具自动配对
- `IOSTANDARD` 用 `LVDS25`
- 如果板子上有 HDMI 电平转换芯片（比如 TMDS 转接），引脚分配和电平要求又不一样，
  以原理图为准

## 五、跑流程

TD 里一条主流程：

```
综合（Synthesis） → 布局布线（Place & Route） → 生成码流（Generate Bitstream）
```

每步都要看报告，重点三条：

1. **综合报告**：有没有 latch 推断、有没有找不到的模块、资源占用是否放得下
2. **时序报告**：clk_pix 的建立时间余量（Setup Slack）必须为正
3. **码流生成**：成功会产出 `.bit` 文件（有的版本是 `.sbit`）

这一步如果 `clk_gen.v` 还是透传占位，也能过——所以别拿「编译通过」当「改好了」。

## 六、烧录

### 方式一：下到 SRAM（调试用，掉电丢失）

最快，改一次烧一次，适合调试。

1. TD 里打开「下载」/「Programmer」工具
2. 选择下载器（USB Cable）
3. 点「扫描」/「Detect」，能识别到 EG4S20 就说明 JTAG 通了
4. 选中生成的 `.bit`，点「下载 / Download」

下载成功后板子立刻开始跑，不用重新上电。

### 方式二：烧到 SPI Flash（掉电保留，成品用）

1. 同样先扫描到器件
2. 选「Flash 编程 / Program Flash」
3. 选 `.bit`（有的版本需要先转成 `.sbit`）
4. 勾选「擦除 → 编程 → 校验」
5. 执行

**烧完还要设启动模式**：板子上通常有个跳线或拨码选择「从 Flash 启动 / 从 JTAG 启动」，
要拨到 Flash（Master SPI）那档。否则重新上电还是空的。

> 第一次不放心的话：先按方式一下载确认画面正常，再烧 Flash。
> 这样万一 Flash 启动有问题，还能用 JTAG 重新覆盖。

## 七、上电自检：按这个顺序排查

烧完没画面，按下面顺序看，能很快定位：

| 现象 | 大概率原因 |
|---|---|
| 显示器「无信号」 | PLL 没替换（时钟不对）/ HDMI 差分对引脚错 / TMDS 原语没接 |
| 有信号但全黑 | `rst_n` 没释放（PLL `locked` 没接对）/ `rgb` 一直为 0 |
| **只有边框、没有任何文字** | `rtl/gen/*.hex` 读不到——路径问题，这是最快的排查信号 |
| 文字在但全是方块/乱码 | 字库 hex 读到了但内容不对（重新跑 `tools/build_rom.py`） |
| 画面撕裂 / 抖动 | 时序没收敛（看 Setup Slack），或 PLL 频率配错 |
| 能显示但按键没反应 | 按键引脚错，或极性反了（`key_n` 是低有效）|
| 跑一会就花屏 | 时序余量不够 / 电源不稳 |

**LED 是好帮手**：`led[0]` 接的是 PLL 的 `locked`，`led[3]` 是场同步翻转。
如果 `led[0]` 不亮，先解决 PLL，别往下查。

---

## 八、改完游戏内容要怎么重新上板

只改了文案 / 数值 / 精灵，**不用重新综合布局布线**，只要换 ROM 内容：

1. `python tools/build_rom.py` 重新生成 `rtl/gen/*.hex`
2. 如果 TD 的 `$readmemh` 是综合时读入的 → 重新综合一次（几分钟）
3. 重新生成码流 → 下载

如果想让「改内容不重新综合」，得把 ROM 初始化挪到上电由外部写入（比如 Flash 里存 hex，
上电用一个状态机搬进 BRAM）——那是另一个功能，这版没做。
