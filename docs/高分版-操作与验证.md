## 1. 本轮实现与评分项

| 方向 | 实际实现 | 证据/边界 |
|---|---|---|
| 核心功能完整性 | FPGA扫描FAT32根目录、BMP解码、最多32张文件目录、指定图片加载、自动/手动播放、保留RPG | 不是原来所有相册页共用一张图；测试反复读取不同文件并核对缓存像素 |
| 显示稳定性 | 单缓存黑场写入、帧边界切换、加载完成后淡入、IO错误重新挂载、坏图可跳过 | 无额外帧缓存；加载期间有黑场，不宣称无缝视频 |
| 基础音频 | 保留PSG三声部、F3 PWM到外接音箱、H11蜂鸣器，增加静音；播放器模式选曲 | 当前HDMI仍为厂商DVI IP，无HDMI音频数据岛；外接音箱的验收口径需以正式答疑为准 |
| 图层/字幕 | 独立ASCII HUD，模式、播放/暂停、文件名、帧号/总数、参数、加载/错误状态，滚动字幕 | HUD在FPGA内生成，不是烘焙进BMP，能现场动态变化 |
| 切图/转场 | 上电ANIM序列；图库手动/自动轮播；图库8档淡出/淡入 | 序列模式采用黑场切换以减少额外停顿，速度受TF读卡限制 |
| 缩放/视图 | BMP不同输入尺寸采样到256×192，正常2倍、缓存原尺寸1倍、中心4倍放大 | 尚无任意宽高比自适应保持比例；NATIVE指缓存像素1:1，不是640×480原图1:1 |
| 实时参数/OSD | 9档亮度、3档对比度、3种视图，参数即调即显 | RGB565逐通道加法/移位/饱和，无新增乘法器用于调色 |
| 音频可视化 | 已有音高+真实音符包络驱动彩条，新增开关及静音/加载遮罩 | 是音高/包络可视化，不是FFT频谱分析 |
| 工程规范 | 目录排序、跨时钟握手、错误恢复、素材工具、独立RTL及集成测试、操作文档 | 新设计模块仍在TD已包含文件中；sim测试文件不能加入综合 |

截图正文将SDRAM、HDMI音频等作为技术方法示例；不能据此宣称每个示例都是独立必做。当前数据路径仍为TF→片内缩略图RAM→HDMI，没有新增SDRAM控制器。

## 2. 模式与按键

物理矩阵键盘沿用原列序映射，同一列的四个键等价。短按在松开时触发，长按约1.2秒触发；长按松开不会再产生短按。

### 播放器普通状态

| 操作 | 功能 |
|---|---|
| 上电 | 立即进入SEQUENCE，扫描卡并加载首图，不再等待10秒 |
| 短按K1 | 上一张；序列模式只在ANIM组内循环，图库在全部目录内循环 |
| 短按K2 | 下一张，同上 |
| 短按K3 | 暂停/自动；2026-10-31修复后加载、淡入淡出期间也接收。已开始的读取完成后停住，未开始的自动切换取消 |
| 短按K4 | SEQUENCE→GALLERY→RPG；刚进入图库默认为暂停，便于现场手动演示 |
| 长按K1 | HUD/滚动字幕显示开关 |
| 长按K2 | 音乐彩条开关 |
| 长按K3 | 静音/恢复；静音时DAC/PWM回中点，彩条也隐藏 |
| 长按K4 | 进入/退出参数设置 |

### 参数设置状态

| 短按 | 功能 |
|---|---|
| K1 | 亮度0～8循环，4为默认 |
| K2 | 对比度LOW/NORMAL/HIGH循环，默认NORMAL |
| K3 | NORMAL/NATIVE/ZOOM循环 |
| K4 | 退出设置 |

设置期间停止自动切图，设置界面强制可见，即使此前关闭HUD也能调节。已经开始的文件加载会正常完成。加载或转场期间的上一张/下一张不排队；待READY且淡入完成后再按，避免连续覆盖单缓存。

### RPG

短按K1～K4仍交给原游戏。长按K4返回SEQUENCE并重新从首图开始。游戏核心未删除；播放器期间屏蔽游戏短按，切回游戏有约0.25秒保护间隔。游戏内部已有计时/动画可继续运行，不承诺暂停所有内部时间。

## 3. TF素材规则与可用演示包

- FAT32、512字节扇区；首个MBR分区0B/0C或LBA0直接为FAT32 BPB。暂不支持exFAT、GPT、子目录。
- BMP为24位BI_RGB，宽至少256，高的绝对值至少192，最大65535。正/负高度、行填充及碎片簇链受支持。
- 只扫描根目录中的短目录项BMP；跳过删除项、长文件名项、目录和卷标。为了可控命名，素材使用8.3文件名。
- 保留发现顺序的前32个BMP，之后停止扫描；然后按名称排序。精确符合 `ANIM` 加4个ASCII数字的8字节主名优先进入序列组，如 `ANIM0001.BMP`、`ANIM0003.BMP`。编号可有间隔，按名字排序播放，不按FAT自然顺序。
- 其他BMP在序列组后按8字节主名排序，图库包含全部保留文件（包括ANIM）。没有ANIM时，序列模式回退到全部BMP。
- 根目录超过32个BMP时，较晚目录位置的ANIM也可能未被保留；演示卡建议只放本次需要的文件且不超过32张。

已提供 `tools/out/media_demo.zip`：8张ANIM打怪/升级/结算示意帧和2张图库海报，全部256×192、24位BMP。这些是演示素材；真实RPG逻辑仍在RPG模式运行。解压后只将10个BMP复制到TF根目录，manifest.json不用复制。不要直接将zip文件放到卡里当图片。

重新生成样例：

```powershell
python tools/prepare_media.py --demo --output tools/out/new_demo
```

从自己的帧图片和图库素材生成：

```powershell
python tools/prepare_media.py --sequence 我的动画帧目录 --gallery 我的图库目录 --output tools/out/my_media
```

工具按输入文件名排序并生成 `ANIM0001.BMP` / `PIC00001.BMP`，默认编码到256×192，默认等比例留黑边；拒绝超过32张。已有非空输出目录默认不覆盖，需显式 `--overwrite`。工具不打开磁盘设备、不格式化、不向TF卡写扇区。它仅做离线素材编码，其留黑边处理不计为FPGA自适应缩放功能；FAT扫描、BMP解析、抽样、调色板、播放控制全部仍在FPGA中完成。

若优先帧加载速度，使用256×192素材；640×480虽可用，每帧仍需读取约922KB，缩小缓存不会减少卡内文件读取量。6.25MHz SPI理论上限0.78MB/s，256×192每帧约148KB，实际帧率还受FAT/命令、加载黑场和控制停留影响。当前不是视频解码器，不保证25/30fps动画。

## 4. 关键实现

- `rtl/common/key_debounce.v`：sd_img新增32项扁平寄存器目录、逐步排序、指定索引加载；新media_ctrl模式/转场/设置，media_cdc请求和完整状态快照的toggle/ack握手。
- 目录项保存 `{basename64, cluster32, size32}`。最终目录实现为512×8位同步RAM，逐项16字节写、32拍读；排序顺序读取两个条目并交换，避免动态索引4096位寄存器产生巨大桶形选择逻辑。不新增扇区缓存或帧RAM，计划使用剩下1块9Kb RAM，实际映射以新TD报告为准。
- `rtl/rpg_top.v`：新控制器替代旧gal_ctrl实例，长按连接，读卡/视频的完整元数据握手，模式对应音乐及静音输出。旧gal_ctrl模块保留但顶层不再实例化。
- `rtl/video/rpg_video.v`：在活动区结束的垂直消隐处发frame_tick；读取画面/OSD/视图/参数/加载遮罩。调色板不变，tf_ram改为三个16384×4区块，避免TD把49152深度扩成65536，减少8块图缓存RAM。延迟区块选择与数据一致，仍为一拍读取。
- OSD生产路径使用两级流水：先寄存文字选择、字模坐标和背景，再寄存字模/背景混合结果；RPG底图、彩条、坐标、控制与HS/VS/DE对齐延迟两拍。顶层在TMDS编码前再将RGB与HS/VS/DE一起寄存一拍。直接图层测试可用PIPELINE=0组合模型，生产rpg_video明确实例化PIPELINE=1。
- `constraints/timing.sdc`新增针对media_cdc握手的约束：四条控制toggle仅按指定net/跨域方向排除异步首级检查；两条payload总线保留30ns最大数据路径、0ns最小延迟。数据在往返确认前保持，接收端经两级控制同步再采样；未整体放宽clk_pix或将50/40MHz所有路径一概排除。
- 下一张加载先淡出或切黑，并至少经过完整帧边界再跨时钟发请求；图片完成后才淡入。写缓存期间不显示旧缓存。
- 格式错误保留目录，便于手动选择/自动跳过。读卡IO错误完成失败请求、撤销目录，3秒后重新初始化、扫描并自动加载首图。
- HUD帧号/数量目前明确标为HEX：例如0A为十进制10，20为十进制32。文件名和状态以实际加载结果为准；失败时文件名保留最后成功值，ERROR明确标示当前失败。

- media_ctrl：上电序列、循环、图库、参数、RPG、错误跳过、黑场请求屏障。

- media_audio：通过真实顶层和物理按键输入，检查实际PCM活动、长按K3静音/恢复和静音PWM50%占空比；只加速仿真中的按键消抖时间，未强制内部信号。

- catalog：ANIM分组、排序、跨根目录簇链、32项上限、不同图片反复加载、坏图/无效索引、读卡中断/重新挂载。

## 6. 现场建议演示顺序

1. 可直接在TD Programmer使用已生成的 `build/media_player/media_player.bit` 下载SRAM；如果改了源码再重新综合/布局布线/生成。插入准备好的FAT32演示卡，上电直接看编号序列。
2. 短按K3暂停，展示画面确实停留；再恢复。
3. 短按K4进入图库，按K1/K2跨不同文件切换，注意HUD文件名和帧号变化；K3开启4秒轮播，展示淡入淡出。
4. 长按K4进设置，分别调整亮度、对比度和视图；展示参数值与图片同时变化。
5. 长按K1展示/关闭滚动字幕，长按K2展示/关闭音乐彩条；接底板音箱播放并以长按K3演示静音。
6. 短按K4退出设置，再短按K4切回RPG，完成一次真实游戏操作；长按K4回播放器。
7. 如需稳定性证明，再用单独测试卡演示坏BMP可恢复，不要在常规演示素材中故意夹坏文件。

本轮未实现：SDRAM帧缓存、HDMI音频数据岛、视频解码、高帧率无缝动画、Flash固化、任意宽高比自适应保持比例。不要在答辩中把这些计为完成。Flash固化应在整机上板稳定后再做。
