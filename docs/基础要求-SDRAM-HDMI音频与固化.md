# 四项基础要求版本：SDRAM、HDMI音频与固化

本页是当前基础要求版本的使用依据。旧“高分版”是256×192/16色片内缓存版本；旧码流保留用于回退。当前版已经实现完整640×480 RGB888的SDRAM双帧显示和真正的HDMI48kHz测试音，保留RPG及K3暂停修复。离线工具验证已完成；板上读图、HDMI声音和Flash断电启动仍需用户实际验收。

## 1. 四条要求对照

| 要求 | 当前工程实现 | 离线证据 | 实物状态 |
|---|---|---|---|
| SPI读取640×480、24位未压缩BMP，解析到SDRAM并HDMI输出 | 原始RGB888逐像素写入片内封装的EM638325 SDRAM，完整307200像素，不量化到16色、不缩成256×192 | 正/负高度原始BMP分别比对307200个唯一像素地址与RGB值；真实SDRAM协议/存储模型读回 | 待用户下载实测 |
| 手动切图、自动轮播、画面连续稳定 | 两个SDRAM帧区，后台加载时持续读前帧，写入全部完成后只在垂直消隐切换；暂停跨加载/转场有效 | 50/40MHz完整FIFO、实际控制器和存储模型，在并行上传时核对前帧8帧及新帧1帧，无正常读空；发布事件等待像素域换帧确认 | 待显示器实测 |
| HDMI48kHz音频测试音，音视频同步播放 | HDMI音频采样包、音频时钟恢复ACR、AVI及Audio InfoFrame、TERC4/BCH、48kHz立体声1kHz正弦测试音；原厂10:1串行化 | 两帧5024个包、1591组样本、2733视频像素独立解码，校验采样/格式/同步/包校验；原厂保护模型实际TD展开 | 待支持音频的HDMI接收设备实测 |
| 固化，上电即可运行 | 已生成TD码流及可选原始Flash二进制，文件容量小于板上2MiB Flash | bitgen成功，源码/资源/时序/文件SHA256校验 | **尚未执行Flash写入与断电启动验证** |

不能将“生成固化文件”说成“板上已固化”。本轮没有自动下载FPGA、写TF卡或写Flash。

## 2. 先做SRAM验收

### 文件

- 新程序：`build/basic_requirements/eg4s20_basic.bit`。
- 新素材：`tools/out/basic_media_640.zip`，包含8张ANIM序列和2张图库图，全部640×480、24位BI_RGB。
- 可选原始Flash文件：`build/basic_requirements/eg4s20_basic.bin`。板卡教程中的ProgramFlash可直接使用.bit，通常不必手动选.bin。
- 证据：同交付目录的 `basic_validation.json`、`base_phy.area`、`base_phy.timing`、`source_sha256.json`、`SHA256SUMS.txt`。

旧256×192素材不符合这一基础版本的严格输入规格，会被报告为格式错误。先备份原素材，解压新素材，将其中10个BMP复制到FAT32卡根目录并覆盖对应旧同名文件；zip和manifest不用放入卡内。现有卡若已为FAT32，不需要重新格式化。根目录建议只保留本次演示BMP，总数不超过32。

### 下载与检查

1. 使用已成功连接的TD Programmer和板卡，识别EG4S20BG256。
2. 选择 **SRAM / FPGA配置**，添加 `eg4s20_basic.bit`，下载并等待成功。
3. 插入上述测试卡，按复位。等待初始化和首图加载；后续读图期间应保留上一张，文件名在新图提交后更新。
4. 看图片是否完整、颜色正常、文字比旧缩略图清楚，有没有横条/错行。默认HDMI输出800×600，640×480原图在物理坐标(80,60)居中1:1显示。
5. 普通播放器短按并松开K3，AUTO应变PAUSED；若正在加载，当前图完成后停住；再按恢复。短按K1/K2手动上一张/下一张；K4依次序列→图库→RPG，RPG长K4回播放器。
6. 用支持HDMI音频的电视/带扬声器显示器，或HDMI音频提取器连接音箱，确认能听到连续1kHz测试音。仅有视频的显示器无法验收声音。
7. 长按K3约1.2秒验证HDMI测试音静音/恢复；短按K3只暂停图像，不停止采样时钟。HDMI测试音与原F3 PWM音乐是两条不同输出路径，当前没有把原PSG曲目重采样搬进HDMI。
8. 在图库自动轮播多次，观察新图到达时是否只有正常的帧边界切换。使用20～30分钟运行和多次复位检查稳定性，再进行Flash固化。

HUD可长按K1关闭以看完整原图。长按K2开关已有PSG音高/包络彩条；它不是HDMI1kHz音源的FFT。全帧设置页短K1亮度、K2对比度、K3开彩条、K4退出；此版不对顺序SDRAM视频流做旧的随机访问缩放视图。图片大小严格640×480，不要将旧NATIVE/ZOOM描述套用到本版。

若首图一直失败：记录HUD状态、两排诊断位、显示器照片。第一排bit7表示内存初始化就绪，bit6表示SDRAM前帧有效，bit5目录找到BMP，bit0～4仍为SD初始化里程碑。初始化就绪和前帧有效是控制状态，不是物理存储芯片读回正确性的替代证明。

## 3. SRAM确认后再ProgramFlash

Flash会替换原来的上电程序。两个旧工作版本保留在 `build/media_player/` 和 `build/media_player_pause_fix/`，可随时重新用SRAM下载回退。先确认新版本的图像和HDMI声音，避免把未经板测的版本固化为默认。

实际核心板原理图U8是M25P16（16Mbit=2MiB）。参考板卡入门文档32～34页的流程：

1. 打开TD Programmer，选择 **ProgramFlash / Flash编程** 模式。
2. 选择实际板卡和下载器，按自动检测或实物丝印确认Flash型号。不要把Flash容量或芯片型号猜成其他型号。
3. 添加 `build/basic_requirements/eg4s20_basic.bit`，按工具界面执行擦除、编程和校验，等待全部成功。
4. 完成后断开供电，再重新上电；不重新执行SRAM下载，确认上电进入序列、TF读图、HDMI声音均正常。
5. 多次断电/上电确认，并记录一次冷启动演示。

该核心板原理图MSEL0=T11通过R92上拉、MSEL1=N11通过R93下拉，配置是固定电阻，不应凭其他板型教程随意移动跳线；两针Config连接的是PROGRAM_B与GND，并非启动模式跳线。若实物版本与该原理图不一致，应按实物原理图核对。

## 4. 实现与验证要点

### SDRAM

EG4S20BG256内部封装EM638325，4银行×2048行×256列×32位，总8MiB，通过EG_PHY_SDRAM_2M_32专用接口使用，不新增顶层外部SDRAM引脚。控制器做JEDEC启动、8次刷新、CAS3模式设置、1～128字突发、跨行/银行、字节掩码、预充电、刷新和物理写完成。同步预取写数据寄存器避免128字组合选择直接赶5ns相位窗口。

PLL保留40/200MHz，并新增控制50MHz与SDRAM50MHz+90°。厂商PLL行为模型验证了20ns周期与+5ns相位。控制器按制造商最慢速度参数留余量；模拟tAC6ns和9ns两档，刷新最大356个时钟=7.12µs，小于15.6µs要求；持续突发读模拟带宽约178.45MB/s。

SDRAM每像素32位字，低24位RGB，两个帧区基址0和0x80000。显示2048×24异步FIFO、写入128×43队列，16字写入/128字预取；活动画面扫描需要约74.12MB/s内存带宽（含每像素32位存储）。整帧写入完成、队列排空、控制器空闲后等待垂直消隐换帧，并由像素域确认后再发布文件名和完成事件。早期写队列溢出/终止也会被记住，不会等不到第二次完成。

### HDMI

新AUDIO_DI_EN=1实际连接并行HDMI编码器和原厂受保护的三个数据串行器、一个时钟串行器。公开端口DP_I/PCLK/SCLK/DSP_O从TD元数据核实，未猜测接口；时钟字0000011111。48kHz采样由40MHz精确分数分频，ACR N=6144、CTS=40000，视频/同步整体延迟11拍，数据岛安排在水平消隐。MIT来源与许可保留在 `sim/hdmi_audio/`。

### 回归命令

```powershell
python tools/verify_basic.py --full --release
```

分项可运行：`verify_full_bmp.py`、`verify_sdram.py`、`verify_framebuffer.py`、`verify_frame_publication.py`、`verify_hdmi_audio.py`、`verify_media_video.py`。命令均在项目根目录运行。本地Icarus自动从tools/iverilog/bin寻找；不需要API密钥。旧verify_sd.py保留缩略图兼容算法和接口检查，不能单独证明本版完整SDRAM路径。

- 完整BMP：正/负高度各307200个唯一RGB888像素，badbpp和错误尺寸拒绝。
- SDRAM：所有突发长度、行/银行边界、最高地址、字节掩码、生产者暂停期间刷新和带宽，两档tAC；是真实存储模型，不是空厂商黑盒。
- 帧缓存：完整上传两幅图，前图8帧和后图1帧，共2764800显示像素；并发上传无正常读空，终止、短帧和故意溢出拒绝；独立FIFO容量/随机停顿/回绕/清除。
- 发布器：从生产顶层提取原always块，检查换帧前不提前发布、早期内存失败、格式失败和同拍完成。
- 视频：完整614400像素两帧，RGB888低位、亮度/对比度、管线、HUD和已有RPG/旧路径兼容测试。
- 音频：5024包、1591立体声采样，BCH/InfoFrame/ACR/IEC60958/1kHz波形、同步与有效画面独立解码；接口stub仅用于端口路由，实际保护串行器已由TD原生编译。
