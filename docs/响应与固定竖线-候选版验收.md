# 响应与固定竖线：候选版验收

本页对应用户实物反馈：K3字样马上变PAUSED但图片稍后才停，K4模式操作感觉慢；分离器现已能出声音，声音为连续“滴”；图片中有四条等距固定细竖线，直连和经分离器都有，关闭叠加后仍存在。屏幕照片为2026-10-31的ANIM0006.BMP/GALLERY/PAUSED场景。

**当前交付是经过离线验证的修复候选，尚未在用户板上验证竖线消失。先SRAM测试，不在本次直接固化Flash。**

## 优先使用的文件

- 主测试固件：`build/response_lines_fix/eg4s20_response_lines.bit`。
- 可选原始文件：同目录 `eg4s20_response_lines.bin`，本轮测试不需要它。
- 对照固件：`build/hdmi_response_compare/eg4s20_controls_cea.bit`，只有即时取消、CEA和默认彩条关闭，保留原SDRAM输出方式。除非需要对照，不要混用。
- 无绘制线条的素材：`tools/out/pixel_line_diagnostics.zip`，含纯灰、纯红、平滑渐变三张640×48024位BMP；用于仍有竖线时进一步定位。

保持现在已经能出声的分离器和音箱接线不变。现有640×48024位素材可继续使用，不需要重新做卡。

## 下载后的检查顺序

1. 在TD Programmer的SRAM/FPGA配置模式，明确重新选择主测试固件，下载成功后复位。
2. 默认输出变为标准640×480/60Hz（VIC1），原图1:1填入有效区域；显示器可能需要重新锁定输入。音乐彩条默认关闭，仍能长按K2开启。
3. 在自动播放正在加载下一张时，短按并松开K3。应该立即保留当前已显示图像，不再等下一张整图完成后跳过去才停；顶部状态变PAUSED。极接近已经完成的换帧边界时，保留已经显示的新帧。
4. 自动播放加载期间短K4进入图库，或再按进入RPG，应该取消未显示的后台图；模式反馈不再等整幅文件读完。首张图尚无任何可显示前帧时仍需先完成初次读取。
5. 对比原照片的四条细竖线：看ASCII标题、HP横条、史莱姆和右侧灰背景。请记录“消失/减少/不变/变成其他样式”，不要仅用字幕状态判断。
6. 需要看原图时长K1关闭HUD。若竖线仍在，用诊断包的TESTGRAY.BMP和TESTGRAD.BMP在同一链路测试并拍全屏；这两张没有人为画竖线。可复制到现有根目录后在图库选它们，注意总BMP数不超过32；测试前备份原卡，不必格式化。

短按动作在松开并通过消抖后产生；长按约1.2秒有不同功能。K1/K2选择一张新图仍需读卡：640×48024位原始像素约0.92MB，当前SPI6.25MHz理论读取就超过1秒。即时取消解决“按暂停/切模式之后又把后台新图显示出来”，不把整图读取时间伪称为零。

## 一直“滴”的声音

这是当前基础版本预设的48kHz采样、1kHz立体声测试音，说明模拟音频提取链已能工作。长K3可以静音/恢复，短K3只暂停图片。当前HDMI尚未接入原PSG游戏曲目；原F3 PWM游戏音源仍保留。因此声音内容不是本次“按键慢”或竖线问题的判断依据。

分离器链路应为：FPGA HDMI→HDMI IN；HDMI OUT→显示器；3.5mm AUDIO/L-R→有源音箱；分离器按标识单独供电。本次用户已确认分离器自身灯亮、模拟音频口接法及音箱发声，不再把这一链路记为无声。若用电脑对照，声音输出选HDMI并设立体声PCM48kHz。

## 本次改动

### 1. 加载可取消

K3暂停或K4切模式时，控制器发送取消请求；请求桥忙时也会排队，不丢一次按键。读卡器只完成当前扇区与CRC，不再继续整幅图，保留目录和上次成功元数据。SDRAM后台帧被终止并排空写入，实际前帧继续扫描。若文件已解码但尚未换帧，则直接终止待提交；若换帧已发生，保留真实新帧元数据，避免文件名与画面不一致。

### 2. CEA视频兼容

输出为640×480p60、800×525总时序，负HS96像素、负VS2行。像素25.2MHz、串行126MHz，AVI VIC1；48kHz音频ACR N6144、CTS25200。厂商计算器实际验证新视频PLL：NOCOMP/VCO_PHASE_0、PFD10MHz/VCO630MHz、REF5/FB63、25/5输出分频。单独保留旧内存PLL的50MHz与+90°5ns关系，不改TF或SDRAM工作频率。

发现并修正了CEA模式下坐标比DE领先1像素的实际回归错误；640个首尾像素和每帧307200请求全部校验。旧800×600模式保留作兼容代码路径。

### 3. 内存接口时序增强

用户照片的重复细线与128字突发边界相符；同名原BMP在右侧背景列511/512的前150行均为正常RGB(12,12,16)，没有照片中的白/彩色细线。这个观察支持继续查显示数据链路，但不能单凭照片证明芯片时序是唯一原因。

独立检查厂家EM638325时序图后，没有发现原CAS3突发终止逻辑的标准错误。原输出由系统上升沿状态经组合逻辑到SDRAM，理想+90°接口只有5ns输出建立窗口，且没有外部dieIO的完整STA模型。

候选把全部SDRAM命令、地址、银行、CKE、掩码、DQ数据及驱动使能放到系统下降沿输出寄存器，波形层面在下一PHY采样前约15ns稳定；读捕获增加一拍与命令延迟一致。CAS3/MRS和时钟相位不变。厂家要求下首次/最后数据、预充电和物理写完成均由独立模型检查，不能拿遮挡线条当作修复。

实际TD报告中，CKE/WE/CAS/RAS及地址由旧NONE变为OREG。内部上升沿到下降沿路径也纳入本次STA，最差建立余量5.436ns，保持余量0.112ns。**15ns是RTL理想端口波形间隔，实际外部die接口还包含时钟/IO/封装延迟，竖线仍需上板对比。**

## 离线验证与边界

- 实际生产控制器：tAC6ns和9ns全长度1～128、行/银行切换、掩码、刷新、慢写入通过。
- 独立CAS流水模型：tAC5.4ns、9ns各49536字，精确首尾字及物理读写次数通过；包括读DQM延迟。
- 写完成距实际最后PRE为55ns；波形端口建立间隔15ns；持续模拟读约177.22MB/s，最大刷新363时钟=7.26µs。
- 实际生产帧缓存：2764800显示像素、21600读突发、38406写突发，后台并发、终止、短帧、溢出、反向BMP行和跨域换帧通过，无正常读空。
- 取消控制/异步请求/实际FAT读取三组、待提交取消与换帧竞争通过；旧39个SPI/SD回归和5个目录回归通过。
- HDMI两种模式独立检查、20000个TMDS向量、BCH长除法、CEA两帧4200包/1599立体声采样、ACR/声道状态/静音/边界通过。
- 视频9组通过：CEA每帧307200请求/像素、首尾RGB888、同步宽度和旧路径。
- 新固件37个源输入与快照一致，TD综合/布局/布线/码流生成成功，内部3个逻辑时钟和4个CDC数据路径组均无违例。三个纯参考/转发时钟没有寄存器端点，不能用0端点替代外部接口证明。
- 路由后LUT14841/19600、寄存器5382、9K RAM45/64、32K RAM16/16、DSP17/29、PLL2/4。混合上升/下降沿的minimum-period字段不作为整机Fmax承诺。
